01
Agentic AI August 2026

Customer Support Chatbot

A support chatbot with three separate routes, where plain code decides when the database may be written to.

The problem

Support bots fail in two common ways: they make up answers, and they save incomplete tickets. This one has three routes that never overlap. It collects bug reports over several turns, answers only from the shop's FAQ, and sends everything else to a person.

What I built

  • An AgentCore Harness on Amazon Nova Pro 1.0 that keeps conversation state across turns.
  • An AgentCore Gateway that gives the model one tool, defined by an OpenAPI contract: a Lambda function that writes bug reports to DynamoDB.
  • A routing guard in plain code that blocks early writes, removes <thinking> tags from replies and handles fallbacks.
  • A Flask web app with login and a panel that shows which route was chosen and the source of each answer.
  • Bedrock evaluation on a JSONL dataset, with a model scoring the answers and a per-case metrics table.

02
Agentic AI September 2026

AI Support Agent

One conversation can track an order, issue a refund, look up a policy, remember the customer, work out a discount and read a website.

The problem

Real support requests need several backend services. An agent with many tools is only useful if every tool has a clear job, and if the final reply keeps the numbers the tools returned.

What I built

  • An async Strands app on AgentCore Runtime using Amazon Nova 2 Lite.
  • An MCP Gateway with two targets: an API Gateway endpoint for orders and a Lambda function for refunds.
  • Bedrock Knowledge Base search over a product catalog in S3, indexed in OpenSearch Serverless.
  • AgentCore Memory hooks that bring back customer preferences in later sessions.
  • Code Interpreter for loyalty discounts (Python Decimal, exact rounding) and Browser for reading live web pages.
  • A check on every reply that copies the calculator's exact figures, so the model cannot restate them wrongly.

03
Agentic AI Capstone October 2026

NovaMart Multi-Agent E-commerce RAG

A supervisor agent sends each question to four specialist agents, which share state and search three knowledge bases at once.

The problem

An e-commerce support question often needs order data, a refund decision and policy text at the same time. A single agent ends up mixing these jobs together. NovaMart gives each job to its own agent and keeps all of their work in one shared, versioned record.

What I built

  • An OrchestratorAgent (Claude Haiku 4.5) with five routing tools, and four Claude Sonnet 4.5 agents for inventory, policy, refunds and the final reply.
  • Parallel RAG: the PolicyAgent searches the Returns, Shipping and Warranty knowledge bases (stored in S3 Vectors) at the same time using a ThreadPoolExecutor.
  • A shared WorkflowState table in DynamoDB with optimistic locking: each write must match the expected version or it retries.
  • AgentCore Memory for seven-day session summaries and a Bedrock Guardrail on the runtime.
  • CloudWatch and X-Ray tracing, CloudFormation and CDK for infrastructure, and GitHub Actions for validation and deployment.
